## 🎯 Цель работы

Освоить базовый рабочий процесс разработки с использованием Git и GitHub:

- клонирование репозитория и работа с ветками;
- осмысленные коммиты и push в удалённый репозиторий;
- работа с системой непрерывной интеграции (GitHub Actions);
- создание Pull Request и взаимодействие с CI-проверками.

---

## ✅ Что нужно сделать

1. **Форкнуть** репозиторий (или клонировать, если преподаватель выдал прямой доступ).
2. **Клонировать** его локально.
3. Создать ветку `feature/<FIO>-add-in-base`.
4. **Реализовать функцию** `add_in_base` в файле `src/sum_in_base.py`.
5. Убедиться, что тесты проходят **локально**: `pytest -v`.
6. Сделать commit изменения **осмысленными коммитами** (минимум 2 коммита).
7. Сделать push ветки в удалённый репозиторий.
8. Убедиться, что **CI отработал успешно** (зелёная галочка на GitHub).
9. Открыть **Pull Request** в `main` с описанием решения.
10. **Не мержить PR** — оставить открытым для проверки преподавателем.

## 📐 Требования к функции

Функция должна складывать два числа, записанных в системе счисления с заданным основанием.

### Сигнатура

```python
def add_in_base(a: str, b: str, base: int) -> str:
    ...
```

### Параметры

| Параметр | Тип   | Описание                                              |
|----------|-------|-------------------------------------------------------|
| `a`      | `str` | Первое число в виде строки, например `"1011"`         |
| `b`      | `str` | Второе число в виде строки, например `"111"`          |
| `base`   | `int` | Основание системы счисления, `2 <= base <= 36`        |

### Возвращаемое значение

Строка — сумма `a + b` в той же системе счисления.

### Примеры

```python
add_in_base("1011", "111", 2)   # -> "10010"
add_in_base("99", "1", 10)      # -> "100"
add_in_base("FF", "1", 16)      # -> "100"
add_in_base("Z", "1", 36)       # -> "10"
```

### Обработка ошибок

Функция должна выбрасывать `ValueError`, если:

- `base < 2` или `base > 36`;
- хотя бы один из операндов содержит символ, недопустимый для данной системы счисления.

## 🚀 Быстрый старт

### 1. Форк и клонирование

```bash
# Через веб-интерфейс GitHub: нажмите "Fork" в правом верхнем углу.
# Затем клонируйте свой форк:
git clone https://github.com/<ваш-логин>/sum-in-base.git
cd sum-in-base
```

### 2. Создание виртуального окружения

```bash
python -m venv .venv

# Linux / macOS
source .venv/bin/activate

# Windows (PowerShell)
.venv\Scripts\Activate.ps1

# Windows (cmd)
.venv\Scripts\activate.bat
```

### 3. Установка зависимостей

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Запуск тестов (должны упасть — это нормально)

```bash
pytest -v
```

Вы увидите ошибки `NotImplementedError` — так и задумано: функция ещё не реализована.

## 🧭 Пошаговая инструкция

### Шаг 1. Создайте рабочую ветку

```bash
git checkout -b feature/add-in-base
```

### Шаг 2. Реализуйте функцию

Откройте `src/sum_in_base.py` и напишите реализацию `add_in_base`.

### Шаг 3. Проверьте локально

```bash
pytest -v
```

Все тесты должны быть зелёными. Если нет — правьте код, а не тесты.

### Шаг 4. Закоммитьте изменения

```bash
git add src/sum_in_base.py
git commit -m "feat: реализована функция add_in_base"
```

> 💡 Рекомендуется делать несколько осмысленных коммитов, например:
> - `feat: добавлен скелет add_in_base`
> - `feat: реализовано сложение столбиком`
> - `fix: обработка неверного основания`

### Шаг 5. Запушьте ветку

```bash
git push -u origin feature/add-in-base
```

### Шаг 6. Проверьте CI

Перейдите на страницу репозитория на GitHub → вкладка **Actions**.
Убедитесь, что workflow для вашей ветки завершился успешно (зелёная галочка ✅).

### Шаг 7. Создайте Pull Request

1. На GitHub появится кнопка **"Compare & pull request"** — нажмите её.
2. Убедитесь, что base = `main`, compare = `feature/add-in-base`.
3. Заполните описание PR:
   - что сделано;
   - как проверялось (локальные тесты, CI);
   - возникшие сложности (по желанию).
4. Нажмите **"Create pull request"**.
5. **НЕ нажимайте "Merge pull request".**

### Шаг 8. Дождитесь CI на PR

На странице PR должен загореться зелёный статус проверки.
Если CI красный — исправьте код, закоммитьте и запушьте снова (PR обновится автоматически).

## ❓ FAQ

**Q: Тесты падают с `NotImplementedError` — это нормально?**
A: Да. Функция ещё не реализована. Ваша задача — сделать так, чтобы тесты стали зелёными.

**Q: Я случайно запушил в `main`. Что делать?**
A: Это штраф.

**Q: CI красный, а локально всё зелёное. Почему?**
A: Проверьте, что запушили последние изменения, что CI использует ту же версию Python,
и что в репозиторий попали все нужные файлы (например, `requirements.txt`).

**Q: Мой PR кто-то должен смержить?**
A: Нет. PR должен остаться открытым. Преподаватель сам проверит и оценит.

**Q: Как перезапустить CI?**
A: CI запускается автоматически на каждый push в ветку PR. Просто сделайте новый коммит
и запушьте.

**Q: Можно ли редактировать тесты?**
A: Нет. Если нашли баг в тестах — сообщите преподавателю.
